# Slope Detector 2
![Features](https://img.shields.io/badge/Polyphonic-No-red.svg?style=flat-square)<br>
The Slope Detector 2 is a 2 HP module designed for slope detection across two independent sections (A and B), identifying whether an input signal is **rising**, **steady**, or **falling**. Section B’s CV input is normalized to section A when no cable is connected, so a single input can drive both sections if needed (e.g. you might opt to output gates in the A section, and triggers in the B section). 

At the top of the module, a **threshold** knob sets detection sensitivity. This knob operates exponentially, covering a range from about **0.00001 V to 0.01 V**, with a default around **0.0001 V**. On each processing step, the module compares the current input value to the previous one for that section. If the absolute difference (delta) meets or exceeds the threshold, the signal is treated as rising (positive delta) or falling (negative delta).

Unlike a simple “what is the slope right now?” check, each section keeps an **active phase**. Once Rise, Steady, or Fall begins, that phase stays active until a **different** phase begins. Rise and Fall can be recognized in a single processing step when the delta crosses the threshold. Steady is different: the input must stay below the threshold (no rise or fall beginning) for the full **Steady hold time** before Steady becomes active. While Rise or Fall is active, the module holds that phase through brief sub-threshold samples until either the opposite slope is detected or the hold time elapses. This avoids falsely declaring Steady during short flat gaps—for example when a slow Infinite-Noise LFO updates its output only every 64th or 256th cycle while the waveform is still ramping.

Each section features three outputs labeled **Rise**, **Steady**, and **Fall**. By default these outputs generate **gates** while the corresponding phase is active (exactly one of the three is high when all are used in gate mode). Each output also has a small push-button: when **green** (default), the output is a gate; when toggled **red**, it switches to **trigger** mode and fires a pulse only when that phase begins. By default, gates and triggers use **10 V high / 0 V low**, but these levels can be changed via the context menu.

![Screenshot of Slope Detector 2](module/SlopeDetector2.png)

**TIP**: In trigger mode, the module outputs a trigger pulse when a phase begins (e.g. at the start of a rise). By using both sections simultaneously, you can also detect when a phase ends. For example, set section A to output a **Rise gate** and feed this gate into section B’s input. Configure B’s Rise and Fall outputs to trigger mode: B’s Rise trigger fires when A enters Rise, and B’s Fall trigger fires when A leaves Rise (e.g. enters Steady or Fall). Using one more SlopeDetector2 module, you can do the same for the Fall- and/or Steady-gates if you in a simiar way need triggers when their respective Fall/Steady phases begins and ends.

**TIP**: If your input signal is very erratic, with frequent small changes, it may be beneficial to route it through a slew module first. This will smooth the signal, making it easier for the module to distinguish between genuine rising, falling, and steady phases. Likewise putting the input-signal through a lowpass filter can also assist "smoothing" the signal, to improve correct phase detection. The **Input smoothing** and **Slope reversal hysteresis** menu items (described below) provide built-in versions of this conditioning.

## Input smoothing
The context menu offers **Input smoothing** (off by default), a built-in one-pole lowpass applied to each section's input before slopes are detected. The **default is Off**, which keeps the default behaviour of comparing two consecutive samples directly (if absolute difference between two consecutive samples exceed threshold either a rise or fall will be detected). The other options are time constants of **0.5, 1, 2, 5, 6, 10, 25, 50 and 100 ms** (menu labels also show the equivalent number of cycles at the current sample rate). Larger values smooth the signal more, suppressing the small, jittery changes that can cause false or rapidly alternating Rise/Fall detection on noisy sources. The smoothing amount automatically adapts when process quality is lowered, so its effect stays consistent. Very large values will also round off and slightly delay genuine edges, so pick the smallest setting that removes the unwanted jitter.

## Slope reversal hysteresis
Also in the context menu, **Slope reversal hysteresis** makes it harder for the active phase to flip straight from Rise to Fall (or Fall to Rise). It requires the opposite-direction delta to exceed the threshold multiplied by the selected factor before reversing an already-active slope; starting a slope from Steady always uses the plain threshold. Options are **Off (1x, default)**, **1.5x**, **2x**, **3x**, and **5x**. At the default (Off/1x) the behaviour is unchanged, reversing as soon as a single opposite delta crosses the threshold. Higher factors ignore brief opposite spikes, reducing rapid toggling between Rise and Fall on jittery signals.

**Warning**: For signals with abrupt voltage changes, such as square waves and gates, start with **Input smoothing Off** and **Slope reversal hysteresis Off (1x)** or low. Strong smoothing turns each edge into a slower ramp and may make its individual deltas too small to cross the threshold. High hysteresis can delay or prevent detection of the opposite edge, especially when combined with smoothing. Increase these settings only when unwanted jitter or false reversals need to be suppressed.

## Steady hold time
Detecting a **rising** or **falling** signal is straightforward. If the delta (the difference between two consecutive samples) exceeds the selected threshold, the signal is classified as either rising or falling. Detecting a **steady phase**, however, is more challenging. To avoid false positives, the module must ensure that the signal is genuinely stable and not merely appearing stable because the source updates its output infrequently. For example, if the source generating the input signal does not produce a new output every processing cycle, the signal may appear steady even though it is not. The context menu includes **Steady hold time**, which sets how long the input must appear steady before the module enters the Steady phase. Options start with **Off**, then **1, 2, 5, 6, 10, 25, 50, 100, 250, and 500 ms**, then **1, 2, 5, and 10 sec**. Menu labels show the equivalent number of audio cycles at the current sample rate (for example `6 ms (288 cycles, default)` at 48 kHz). When set to **Off**, a connected section never enters Steady and detects only Rise and Fall; a section without an input remains Steady.

The **default is 6 ms**. At both 44.1 kHz and 48 kHz this is slightly longer than the longest gap (255 samples) between updates when an Infinite-Noise source runs at **Very low** process quality (every 256th cycle), which helps prevent false Steady detection on CV from slow LFOs and similar modules. Shorter hold times react faster to true plateaus, but may declare Steady too soon when the input is held constant between sparse updates. Longer hold times demand a more sustained flat signal—fine for square-wave flats, while brief crests on a sine may never qualify as Steady.

**Warning**: When detecting **steady phases**, keep in mind that if the input signal is **not updated every processing cycle**, changes are detected less frequently, but each detected change is typically larger. As a result, **SlopeDetector2** will usually require a **higher threshold** to recognize steady phases; otherwise, those changes may be interpreted as rising or falling instead. This can occur, for example, when the input comes from a slow Infinite-Noise LFO. As the LFO frequency decreases, modules such as **Tiny LFO** update their outputs less frequently, increasing the voltage difference between consecutive samples.

**TIP**: If you're unable to detect steady phases reliably, there are several things you can try:
1. **Increase the threshold.** Start by turning the **Threshold** knob fully clockwise. Once steady phases are detected, gradually reduce the threshold until you find the desired balance.
2. **Adjust the "Steady Hold Time".** This setting is available in the context menu and can improve steady-phase detection depending on the input signal.
3. **Increase the source module's processing quality.** If the input comes from an Infinite-Noise module running below **Audio** quality, set its **Process Quality** to **Audio** so it updates every processing cycle. If the module is currently in **Auto** mode (as with the Infinite-Noise LFOs), you'll first need to disable **Auto** before you can manually select **Audio** quality.

## Process quality and warning light
Like other Infinite-Noise modules, Slope Detector 2 lets you lower **process quality** to reduce CPU usage (default is **Audio**, every cycle). The threshold is scaled automatically when process quality is lowered, because each evaluation then spans more samples.

The **red warning light** above the threshold knob illuminates when an enabled timing setting is shorter than one process interval and therefore cannot be represented accurately at the current process quality. This applies to both **Steady hold time** and **Input smoothing**; their Off settings do not warn. The light's tooltip lists every active cause as **Hold**, **Smoothing**, or **Hold, Smoothing**. 

For example, at 48 kHz a **5 ms** setting spans 240 cycles, so either a 5 ms hold or 5 ms smoothing lights the warning at **Very low** process quality (256 cycles). A **6 ms** setting spans 288 cycles and does not. The warning is refreshed when hold time, smoothing, hysteresis, process quality, or sample rate changes. Increase the affected timing setting or raise process quality to clear it.
