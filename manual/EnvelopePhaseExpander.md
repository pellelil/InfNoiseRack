# Envelope Phase Expander
![Features](features/Expander--for-ADR--Envelope-green.svg)
![Features](features/Expander--for-ADSDR--Envelope-green.svg)
![Features](features/Polyphonic-No-red.svg)<br>
The Envelope Phase Expander (**EPE**) can be used as an **expander for ADR Envelope or ADSDR Envelope** and outputs **gates** for the active envelope phase (Attack, Decay, Sustain, Delay, Release and Idle), plus envelope movement (Rise, Steady and Fall). *Since the ADR Envelope don't have a decay phase, the decay output will only output low-gate (default 0V) when used to expand and ADR Envelope.* The Idle jack can instead output **phase position** (0V to 10V) via the context menu. *Some general info regarding these modules are listed in [Common envelope features](commonEnvelope.md).*

The **Expander-mode** will default to **Auto**  (changed via context menu), where it will automatic detect an ADR/ADSDR Envelope module to its left or right side. If there is both an Expander module to its left and right, **you must set a forced Left- or Right expander-mode**. In the top of the module below the "EPE" label you see two lights. These lights indicate the connection-state of the module.

+ **Green** on the left or right = that side is the active host.
+ **Red** = a problem for that side (or both sides in Auto when there is no unique host).
+ **Off** = that side is not used for the current Expander-mode.

**Auto** (default): connect when exactly one neighbor is an ADR/ADSDR Envelope. If both sides are envelopes, both lights go red and no gates are driven until you choose Left or Right. **Left** / **Right**: always use that side; red on that light if no envelope is there, otherwise green. *Basically "what you want to see" is a sigle green light, indicating if it is connected to an Envelope module on its left- or right side.*

The first six outputs are **mutually exclusive phase gates** (exactly one high at a time). A phase that is skipped (time=0) never becomes active, so its gate stays low. **Decay** stays low for ADR Envelope (that module has no Decay stage). **Idle** is high while the envelope holds at R.level after Release (or at init).

**Idle output-mode** (context menu) defaults to **Gate**. Set it to **Phase position (0V to 10V)** to use the Idle jack as a CV for progress through the current timed stage. A **red light** to the left of the Idle label is lit in that mode. Attack, Decay, Delay and Release output the current stage position scaled to 0V–10V (linear in time, not shaped — use **Env** for the shaped envelope). The CV starts over when a new stage begins. Sustain and Idle are untimed holds, so they use **Sustain voltage** (default 10V) and **Idle voltage** (default 0V) from the same menu. Delay is timed and uses live phase position. When no envelope is connected, this jack is 0V. Gate high/low still only apply to the remaining gate outputs.

Likewise the last three outputs are also **mutually exclusive movement gates** (exactly one high at a time). In a typical envelope attack is always a rise, whereas decay and release are typical falls. However as you can freely set A.level, Sustain and R.level for an ADSDR Envelope, this is not set in stone (e.g. the Attack can be fall, and/or the Decay can be a rise). Rise and Fall detection occur on the first moving sample. However **Stdy** waits until the envelope has been unchanged for several successive cycles. How many is set by **Steady hold** in the context menu (default is **3 cycles** with option for: Immediate / 2 / 4 / 6 / 8 / 12 / 16 / 32 / 64 / 128 / 256 cycles). As a result, a Rise/Fall-stage might be "hold" for a few cycles "longer" and there will be a few cycles "delay" before a Steady-stage is detected.

This "Steady hold" exists because **a cable in VCV typically "delays" a signal by 1 cycle**: what one module writes "this cycle" is usually not seen by the receiving module until the "next cycle". If you patch a phase-end trigger (e.g. "EOA") back into a trig input (e.g. "DR.trig"), the envelope will therefore "hold" at the exact same level for one cycle **per cable**. Without this hold, **Stdy** would go high during that "wait" even though Delay/Release is about to start (without this "hold" the "Stdy" output would go high for 1 cycle). The default of **3 cycles** covers a **direct** cable from **EOA** / **BOS** into **DR.trig** / **DlR.trig** (one hop, plus a possible extra flat sample at the phase seam). If you add another module in that loop (for example EOA → another module → D.trig), raise **Steady hold** by about one cycle per extra cable (not to forget that the "inserted module" internally cound introduce "a short delay"). *If it is not super important for your usage that the Stdy output fires exactly when a steady phase begins, you could set "Steady hold" to 16 (16 cycles at 48 kHz is approx 1/3000 s ≈ 0.333 ms) or all the way up to 256 (256 cycles at 48 kHz is approx 1/187.5 s ≈ 5.333 ms).*

**TIP**: If you need to check multiple phases at the same time, you might want to use this module with a [Logic Comparator-6x2](LCMP6x2.md). E.g. pass both the Attack- and Decay outputs into the same section of the Logic Comparator-6x2 and set the logic 3-way switch to **OR**, in order to generate a high gate, when the envelop is either in the Attack or Decay phase. *Alternative simply route both the Attack- and Decay-gates into the same input. When multiple cables are connected to the same input, all signals will simply be added. However as Attack and Decay are never high at the same time, the receiving input will by default either see 10V if one of these are high, or 0V if neither are high.*

**TIP**: When **Idle output-mode** is set to **Phase position**, the Idle port outputs the current stage as 0V–10V. To get that CV **only while a chosen phase is active**, you can patch **Idle** (phase position) into the **A** input of a [Ring Modulator 3](RingMod3.md#ring-modulator-3) section and that phase's **gate** (Attack, Decay, Delay, Release, …) into **B**. By default **B is divided by 10**, so a 10V gate becomes 1 and a 0V gate becomes 0. The section multiplies A by that 0 or 1: the output stays **0V** while the phase is inactive, and follows the **phase position (0V–10V)** while it is active. 

The Ring Modulator 3 (RM3) module has three sections, so you can use the same Idle CV with three different phase gates at once. For that, **swap A and B** so B-normalization can share one phase position cable: in the RM3 context menu set all three **A** inputs to **divide by 10 (/10)** and all three **B** inputs to **1x (no scaling)**. Patch **Idle** (phase position) into **B1** only (B2 and B3 are normalized to the previous B, so they use the same signal). Patch one phase gate into each of **A1**, **A2** and **A3**. Each section then outputs that phase’s position (0V–10V) while its gate is high (A-input), and **0V** otherwise.
